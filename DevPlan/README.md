# 개발 플랜 — 세션 단위 분할

기획서 28장 마일스톤(M0~M8)을 **개발 세션 20개**로 쪼갠 실행 계획. 한 세션이 한 브리프를 맡아, Claude가 적당한 크기의 컨텍스트로 개발할 수 있게 한다.

## 세션 진행 프로토콜
1. **시작**: `PROGRESS.md` 읽기 → 맡은 브리프(`sessions/Sxx-*.md`) 읽기 → 브리프가 지정한 기획서 장만 발췌해 읽기
2. **개발**: 브리프의 In 범위만. Out 범위는 미리 만들지 않는다
3. **종료**: 완료 기준 검증 → `PROGRESS.md` 갱신 (완료 항목 / 다음 세션 인계 메모 / 개발 중 바뀐 결정)

## 원칙
- **순서 ≠ 강제 직렬**: 선행 조건만 지키면 일부는 순서 조정 가능 (예: S05는 S02~S04와 독립, S11은 S09~S10과 병렬 가능)
- **S04b가 첫 관문**: 맵 화면의 수직 슬라이스("구경+개입")가 재미없으면 이후 세션을 진행하지 않고 루프를 재설계한다. 게임은 탭 UI가 아니라 **Rusty's Retirement형 맵+유닛** (기획서 2-2장 — 방향 전환 기록은 PROGRESS 참조)
- **아트 트랙(A)은 별도**: 모든 S세션은 플레이스홀더로 개발. 최종 아트는 전부 PixelLab MCP로 생성 (유저 확정 방침) — 아래 A트랙 참조
